01 · Overview
◆ Brief

Overview

Almas is a Hyderabadi restaurant with a curated Lebanese / Arabic menu — rooted in the old city, anchored by slow-fire cooking. The website is the brand's front door.

Scope

  • Single-page marketing website: hero, signature dish, menu, story, reservation, footer.
  • Responsive from 375 px mobile to 1440+ px desktop.
  • Static site acceptable — no CMS required for v1. Reservation form submits to email / WhatsApp for now.
  • SEO-optimized: semantic HTML, Open Graph tags, JSON-LD for Restaurant schema.

Brand posture

  • Warm, analog, old-world. Think printed menu, not app screen.
  • Serif body copy throughout. Sans-serif is off-brand.
  • Copper & cream palette. Never pure white. Never pure black.
  • No emoji. Use the ornamental diamond (◆) as the celebratory glyph.
  • Motion is slow and confident. 280–520 ms fades. No bouncy springs, no hover scale.

Rules

  • Body copy is serif. 18 px base, 1.55 line-height, Cormorant Garamond. Never sans.
  • Display is UPPERCASE with 0.08–0.18 em tracking. Never tight caps.
  • The script font is used once per surface — as the "Almas" signature. Never in running text.
  • Italic serif (Playfair) carries pull-quotes, dish names, descriptive captions.
  • Arabic text uses Amiri, RTL, same color as body ink.

Single scrolling marketing page. Seven sections, top to bottom. Reference build: ui_kits/website/index.html.

06 · Reserve — centered card, gold inset frameName · Phone · Guests · Date · Confirm
07 · Footer — ink-900 dark, 4-colMark · Visit · Hours · Follow

Layout rules

  • Max content width: 1280 px for marketing sections; 820 px for the menu reading column.
  • Gutters: 24 px mobile, 48 px tablet+, 64+ px desktop centered.
  • Section rhythm: 120 px vertical padding between sections on desktop, 64 px mobile.
  • Grid: 8 px base. Every margin/padding is a multiple of 8.
  • Sticky header blurs the content behind via backdrop-filter: blur(14px) over rgba(251,246,239,0.82).

07 · Voice
◆ Content

Voice & Copy

Almas speaks like a host welcoming you in, not a vendor selling to you. Warm, generous, unhurried, proud of process. No exclamation points. No emoji.

Rules

  • "We" for the house, "you" for the guest. "We marinate for ten hours so you taste every layer."
  • Sentence case in paragraphs. UPPERCASE only for buttons, section headers, eyebrows.
  • No emoji. No exclamation points. Use the diamond ◆ for celebration.
  • Numerals under ten spelled out in prose. Prices always as numerals.
  • Arabic and Urdu words welcome, italicized on first use — mandi, dum, haleem, shawarma, kunafa, khubz.
✓ Do — house voice Our biryani is cooked in sealed clay, one pot at a time. Order by six, we start your pot at seven.
✗ Don't — generic Delicious authentic Indian food!! Click here to order now 🔥

08 · Engineering
◆ Engineering Notes

Implementation

Stack suggestion (flexible)

  • Framework: Next.js, Astro, or plain HTML — whatever your team prefers. Single page + small API route for the reservation form.
  • CSS: Use colors_and_type.css as the token source. Author components with plain CSS or a utility layer on top — no Bootstrap, no Material, no Chakra.
  • Images: serve WebP with JPG fallback. Cap hero at 1920 px. Lazy-load below the fold.
  • Fonts: self-host Kultum Ramadhan; <link rel="preconnect"> Google Fonts for the rest. font-display: swap everywhere.

Must-have

  • Semantic HTML: <header>, <main>, <section>, <footer>, <nav>.
  • Open Graph + Twitter card meta tags (use the Charminar poster as default og:image).
  • JSON-LD structured data with @type: Restaurant including address, hours, phone, menu URL, cuisine types (Indian, Hyderabadi, Middle Eastern).
  • Accessible: all interactive elements keyboard-navigable; focus states visible (gold ring); labels on all form fields; alt on every image.
  • prefers-reduced-motion: disable scroll animations and transitions.
  • Arabic content: set dir="rtl" on the Urdu/Arabic elements, lang="ar" attribute.

Reservation form

V1 submits to email (e.g. reservations@almas.co) or a WhatsApp deep link. No backend DB required. Honeypot field for spam protection. Show confirmation toast (pistachio background), auto-dismiss at 3.2 s.
